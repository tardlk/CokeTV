# 爬虫开发：接入 CokeTV 网盘能力

适用范围：已包含统一网盘模块的 CokeTV 版本。当前统一账号与分享播放仅支持 **115 网盘**；本机开发版已接入，不能据此认定较早的 GHCR 镜像也包含该功能。

爬虫负责搜索资源、读取影片信息、取得分享链接。管理员在后台“网盘管理”扫码登录后，CokeTV 负责读取分享目录、展开视频分集、获取临时播放地址。爬虫不需要处理 115 登录、Cookie 或下载接口。

## 1. 最快接入方式

在影片**详情**结果的 `vod_play_url` 中返回完整的 115 分享链接：

```json
{
  "list": [
    {
      "vod_id": "movie-001",
      "vod_name": "示例影片",
      "vod_play_from": "115网盘",
      "vod_play_url": "分享目录$https://115cdn.com/s/EXAMPLE?password=AB12"
    }
  ]
}
```

以上及下文中的 `EXAMPLE`、`AB12` 均为占位值，不是真实分享或提取码。实际开发时替换为搜索站点提供的资源。

调用顺序如下：

```text
搜索站点 → 爬虫详情返回分享链接 → CokeTV 读取目录并生成分集
                                         ↓
                         用户选集 → CokeTV 取地址 → 客户端播放
```

详情经过宿主处理后，播放线路会类似：

```text
第1集.mkv$coketv-netdisk:115:<随机引用>#第2集.mkv$coketv-netdisk:115:<随机引用>
```

这些引用由服务器生成。客户端照常提交所选分集的播放 ID 即可；宿主识别后直接处理，不再调用该源的 `lazy` / `playerContent`。爬虫不要生成、拆解或持久保存内部引用。

## 2. 当前能力与边界

| 能力 | 当前行为 |
| --- | --- |
| 账号 | 管理员扫码登录一个 115 账号，供多个源和订阅共用；失效后重新扫码 |
| 分享读取 | 读取分享中的视频，遍历子目录并处理分页，按文件名自然排序 |
| 分集 | 视频文件展开为可选分集；非视频文件不列入播放列表 |
| 播放 | 获取平台返回的文件媒体地址及必要请求头 |
| 使用入口 | 网页、TVBox、猫影视共用宿主网盘处理逻辑，各自保留原入口的权限规则 |
| 文件操作 | 当前链路不转存、不上传、不删除网盘文件 |
| 其他网盘 | 既有兼容辅助库保留，但尚未接入这套统一账号与详情自动展开能力 |

视频按扩展名筛选，当前包括 `mp4`、`mkv`、`webm`、`m4v`、`mov`、`avi`、`flv`、`ts`、`m2ts`、`mpeg`、`mpg`、`wmv`、`3gp`。列入分集不代表客户端一定能解码该文件。

这里的“网盘能力”通过标准详情结果交接。当前没有供源脚本导入的 `coketv_sdk` 包，也没有对源开放 `getDriveFileList()`、`getDriveVideoPlayInfo()` 等函数。不要从脚本调用 `/admin/netdisk/*`，也不要要求用户把管理密码或 115 Cookie 填入本源 ENV。

本指南参考了 [OmniBox 爬虫开发介绍](https://omnibox-gamma.vercel.app/spider-development/introduction.html) 和 [SDK 说明](https://omnibox-gamma.vercel.app/spider-development/sdk.html) 的开发者说明思路。OmniBox 文档中的 `omnibox_sdk`、`spider_runner` 及网盘调用方式属于它自己的接口；CokeTV 仍使用已有的 drpyS、DR2、CatVod、HIPY/Python、PHP 源协议。

## 3. 分享链接与详情格式

### 支持的链接

接受以下精确域名的 `/s/<分享标识>` 路径：

```text
https://115.com/s/EXAMPLE?password=AB12
https://115cdn.com/s/EXAMPLE?password=AB12
https://anxia.com/s/EXAMPLE?password=AB12
```

建议始终返回 HTTPS 完整链接。分享标识须为字母或数字；提取码通过查询参数 `password` 提供，允许 0–20 位字母或数字，无提取码时可省略参数。子域名、短链、站点跳转页、带非默认端口或 URL 账号密码的地址不属于支持格式。

如果站点把提取码放在旁边的文字里，爬虫应提取并拼入 `password` 参数。不要返回“链接：…… 提取码：……”这整段文本；也不要只把提取码放在片名、播放线路名或 `vod_content` 中。

推荐构造方式：

```js
const share = new URL(shareURL); // 已从站点取到的完整 115 分享链接
if (receiveCode) share.searchParams.set('password', receiveCode);
const playURL = '分享目录$' + share.href;
```

分享链接还可包在 `push://` 中，后面使用完整 URL 的百分号编码：

```js
const playURL = '分享目录$push://' + encodeURIComponent(share.href);
```

`push://` 是播放条目的包装方式，并不新增推送 HTTP 接口。普通完整链接已经够用。

### 分隔符与多线路

沿用原详情协议：`vod_play_from` 中的线路用 `$$$` 分隔；`vod_play_url` 中相应线路也用 `$$$` 分隔；一条线路的多个播放条目用 `#` 分隔；每个条目为 `名称$地址`。

```json
{
  "list": [
    {
      "vod_id": "movie-001",
      "vod_name": "示例影片",
      "vod_play_from": "115资源一$$$115资源二$$$普通线路",
      "vod_play_url": "分享$https://115cdn.com/s/EXAMPLE1?password=AB12$$$分享$https://115.com/s/EXAMPLE2?password=CD34$$$正片$https://example.invalid/video.mp4"
    }
  ]
}
```

宿主逐个展开被识别的 115 分享，保留普通线路及原线路名。每个分享会替换成其视频分集；原来的“分享”条目名不会成为所有视频的集名。自动生成的集名取自文件名，文件名里的 `$`、`#` 会替换为空格，避免破坏协议。

爬虫生成条目名时同样应避开 `$`、`#`；不要在分享 URL 后附加含 `#` 的片段或说明文字。多线路时，两组字段的线路顺序和数量应一致。

### 什么时候会处理

宿主在标准详情调用（`ac=detail` 且有 `ids`）之后处理结果。支持 `{list: [...]}`、单个含 `vod_play_url` 的影片对象、影片数组，以及以上结构的 JSON 字符串；实际返回形式仍需符合所用引擎的详情协议。

搜索结果通常返回影片 ID、名称、封面等，由详情再取得分享链接。仅在搜索结果、影片介绍、`lazy` 或 `playerContent` 中返回分享网页，不会触发这一详情展开流程。遇到只在播放阶段给出分享的旧脚本，应把取得分享链接的步骤移到详情阶段。

## 4. JS / drpyS 示例

下面是已有 drpyS 规则中的**详情方法片段**。搜索、分类等方法继续按原规则编写；`shareURL` 应由实际站点详情解析取得。

```js
二级: async function () {
    // 示例占位地址；这里替换为读取站点详情后取得的真实分享。
    const shareURL = 'https://115cdn.com/s/EXAMPLE?password=AB12';
    return {
        vod_id: this.orId,
        vod_name: '示例影片',
        vod_play_from: '115网盘',
        vod_play_url: '分享目录$' + shareURL,
    };
},
```

它位于已有的 `var rule = {...}` 内，不是独立可运行的完整爬虫。纯网盘条目无需在 `lazy` 中处理内部引用；如果源还提供普通媒体线路，其原有 `lazy` 逻辑继续负责那些线路。

## 5. Python / HIPY 示例

下面是已有 HIPY `Spider` 类中的**详情方法片段**：

```python
def detailContent(self, ids):
    # 示例占位地址；这里替换为站点详情实际返回的分享。
    share_url = "https://115cdn.com/s/EXAMPLE?password=AB12"
    return {"list": [{
        "vod_id": ids[0],
        "vod_name": "示例影片",
        "vod_play_from": "115网盘",
        "vod_play_url": "分享目录$" + share_url,
    }]}
```

如需使用 `push://`，可使用标准库：

```python
from urllib.parse import quote

play_url = "分享目录$push://" + quote(share_url, safe="")
```

保留原 `Spider` 的初始化、搜索等方法及所需基类。CatVod、DR2 和 PHP 源同样在各自详情方法中返回对应标准字段，不需要为网盘另换执行器。

## 6. 播放、缓存与账号

分享目录默认缓存约 10 分钟，内部随机分集引用默认最长 12 小时，并可能因容量回收提前失效。引用只存在服务进程内，绑定当前源实例和账号版本；服务器重启、账号更新或引用过期后，客户端应重新请求详情，再选择分集。不要把引用写进长期配置或跨源复用。

网页与猫影视通过宿主媒体票据播放；TVBox 播放接口返回临时上游媒体地址及必要请求头。平台地址有有效期，客户端需要保留返回的媒体头；不要把媒体地址当作永久链接保存。账号 Cookie 不出现在这些播放响应中。

原源启用状态、订阅启用状态、Token 和成员范围继续生效。账号更新后旧网页/猫影视网盘媒体票据的新请求会被拒绝；已经缓冲的数据，以及已经下发的平台直链，不能由宿主追溯收回。

当前使用平台文件下载地址播放，没有统一的清晰度选择、转码任务或浏览器音视频格式转换接口。“网盘资源”也不意味着必然是 4K；画质取决于文件本身，能否解码取决于客户端。大体积 MKV 的大幅跳转可能需要较长缓冲。

账号由宿主保存，正常爬虫交接无需访问账号文件。源脚本仍与宿主同权限执行，这套账号管理不是脚本沙箱；只安装可信脚本，详见 [安全边界](../SECURITY.md)。

## 7. 限制与排错

以下是当前默认保护上限，不是建议爬虫每次用满的配额：

| 项目 | 默认上限 |
| --- | --- |
| 单次详情展开的分享条目 | 8 个，按该次详情全部影片合计 |
| 同时读取不同分享的任务 | 4 个 |
| 单个分享的视频文件 | 10,000 个 |
| 单个分享的目录计数 | 500 个，包含根目录 |
| 单个分享的列表请求 | 200 次，包含目录分页 |

遇到读取错误或超限，当前详情请求会失败，不保证仍能返回同次请求里的普通线路。搜索站点应优先提供范围明确的影片/剧集分享，避免一次返回整个大型资源库。

| 现象 | 排查方式 |
| --- | --- |
| 提示尚未登录或登录失效 | 请管理员在“网盘管理”扫码；页面“已保存登录信息”仅表示本地保存过凭据，不保证平台会话永久有效 |
| 详情仍显示一条分享网页 | 检查是否在详情 `vod_play_url` 返回、域名/路径是否规范、提取码是否在 `password` 参数，以及服务版本是否包含网盘模块 |
| 提示分集引用无效或过期 | 重新请求同一源的影片详情，不复用旧引用或另一源的引用 |
| 提示分享失效或没有视频 | 检查分享与提取码，确认目录中有支持的视频文件；字幕、图片等不作为视频分集 |
| 提示读取繁忙或超过上限 | 稍后重试，减少详情中的分享数或选择更小的分享目录 |
| 能取得地址但黑屏、没声音或拖动缓慢 | 检查客户端格式/编码支持、网络和平台权限；这不等于爬虫需要再次解析分享网页 |

## 8. 开发验收清单

1. 使用独立测试源和自己有权访问的分享，保留既有源与数据。
2. 管理员完成扫码；搜索能进入详情，详情中的分享展开为预期分集。
3. 验证带提取码、子目录、自然集数排序、多分享和普通线路混合场景。
4. 验证首集开播、切集、拖动；需要支持手机/TVBox/猫影视时，在对应真实客户端验证解码与声音。
5. 验证服务器重启后账号保留，客户端重新获取详情可以播放；旧引用失效时有明确提示。
6. 分享链接、提取码、账号凭据、临时媒体签名不要写入公开日志或提交的测试样本。
